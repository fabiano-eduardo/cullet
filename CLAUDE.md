# cullet — context for AI agents

## What this project is

`cullet` is an opinionated catalog of architectural TypeScript kits. It ships a CLI and a set of kits that consumers can use in two ways:

- **Direct import**: `import { Entity } from 'cullet/erp-core'`
- **Full-control copy**: `npx cullet fc erp-core@1.0.0` (copies kit source into the consumer project)

## Key directories

| Path | Purpose |
|------|---------|
| `kits/` | Kit source, one folder per kit/version |
| `registry/` | JSON catalog consumed by the CLI |
| `cli/` | CLI entry point (`cullet list`, `cullet doctor`, `cullet fc`, `cullet inspect`) |
| `dist/` | Built output (gitignored, regenerated by `npm run build`) |
| `scripts/` | Build helpers: `sync-package-exports.mjs`, `validate-kit.mjs`, `new-kit.mjs` |
| `templates/` | Scaffolding templates used by `new-kit` |
| `tests/` | Unit and E2E test suites |

## Development commands

```bash
npm run build          # tsup build (runs sync-exports first)
npm run typecheck      # tsc --noEmit (both tsconfig.json and tsconfig.test.json)
npm run test           # vitest unit tests
npm run test:e2e       # vitest E2E smoke tests
npm run validate-kits  # validates registry integrity
npm run sync-exports   # syncs package.json exports from kits/
npm run release:dry-run  # build + pack + check contents (no publish)
```

## Release process

Releases are fully automated via GitHub Actions (`.github/workflows/release.yml`).

**How to release:**
1. Bump version in `package.json` and update `CHANGELOG.md`
2. Commit, then create and push a `v*` tag:
   ```bash
   git tag v0.x.y
   git push origin v0.x.y
   ```
3. The workflow runs: typecheck → validate-kits → sync-exports:check → tests → e2e → build → pack-validate → publish → GitHub Release.

**npm authentication: Trusted Publishing via OIDC (no token needed)**

This project uses [npm Trusted Publishing](https://docs.npmjs.com/generating-provenance-statements#using-third-party-package-publishing-tools) (OIDC-based), configured on npmjs.com under the package settings. There is **no `NPM_TOKEN` secret** — the GitHub Actions workflow authenticates directly via the OIDC token (`id-token: write` permission). Do not add `NODE_AUTH_TOKEN` or any npm secret to the workflow.

The publish command is:
```bash
npm publish --provenance --access public
```

`--provenance` attaches a signed provenance attestation to the published package.

## Adding a new kit

```bash
npm run new-kit
```

Follow the prompts. The script scaffolds the kit under `kits/` and updates `registry/`.

## Constraints and conventions

- ESM-only (`"type": "module"` in `package.json`).
- Node ≥ 18.
- `pino` is an optional peer dependency; `zod` is a required peer dependency.
- `dist/`, `node_modules/`, `*.tgz`, `tmp/` are gitignored and should never be committed.
- Never commit secrets, tokens, or credentials. Auth is handled via OIDC — no secrets needed.
